# 联机跨维度传送导致对战客户端崩溃

2026-10-16，1.4.4 本地修订，包含于 1.4.4 发布；本轮测试客户端已由用户确认通过。此前追加的技能回忆师适配已按用户要求取消，未进行该项修改。

## 报告与原因

报告运行 Java 11.0.15，崩溃是客户端 `Rendering screen` 空指针，起点为本体 `ClientBattleManager.selectedMove(boolean)` 第 749 行，调用方为 `ChooseAttack.render`。不是之前非 Java 11 的空招式问题。

时间线：房主在 `pixelmon:ultra_space` 进行太晶团战；18:58:51.371 另一玩家执行 TP 到房主身边；18:58:51.695 开始生成崩溃报告。日志实际显示传送的是另一玩家，不是房主被移动。房主客户端退出同时导致内置局域网服务器停止。后续异步存储异常发生在关闭阶段，不是这次首个崩溃点。

本体 `ClientProxy.onDimensionChange(PlayerChangedDimensionEvent)` 未判断事件玩家，直接设置全局 `battleManager.battleEnded=true`。内置服务器会在同一进程向事件总线发布所有玩家的维度变化，其他玩家跨维度到场也会错误影响房主的客户端对战状态。这一错误写入已用实际本体方法复现。

本体关闭对战时清空 `teamPokemon`、`fullOurPokemon` 并将控制器索引设为 -1；残留选招界面可能通过场外队伍回退取得宝可梦，再调用未保护的 `selectedMove`，对空的 `teamPokemon` 取长度。离线用例在这个清理后状态执行本体原始字节码，复现同一方法同一第 749 行空指针。报告没有记录全部中间字段快照，因此清理到残留界面的完整现场时序仍需联机复测。

## 修复

- 客户端维度事件只允许本机玩家 UUID 对应的事件进入原生处理。客户端玩家与内置服务器玩家不是同一对象，按 UUID 判断，保留本人跨维度的原生行为。其他玩家事件、本地玩家缺失、事件玩家缺失均不改本机对战。
- `ChooseAttack.render/click` 在对战结束、控制器无效或对战队伍数据缺失时不执行选招逻辑；不读取场外队伍代替场内数据，不发送动作，不编造胜负或奖励。正常对战恢复数据后继续走原生逻辑。
- 两项 Mixin 均仅注册在 client 区，专用服务端不加载客户端类。正常 TP 不被禁止，不新增传送限制，不更改伤害、太晶、羁绊、捕捉或掉落规则。

## 验证与复测

`MixinApplicationVerification` 对实际本体 `ClientProxy` 和 `ChooseAttack` 注入并检查字节码；`BattleTeleportVerification` 执行实际原生／修复后维度监听方法、原生选招方法和生产界面保护回调。

- 原生其他玩家维度事件误结束本机对战，以及原生第 749 行空队伍崩溃均复现。
- 修复后 1,000 次其他玩家事件，不改变本机对战标记、队伍对象、已排队动作和特殊机制选择；覆盖观战标记。
- 本人相同 UUID、不同实体对象仍执行原生结束标记；没有客户端玩家／事件玩家时安全跳过。
- 空管理器、空队伍、空完整队伍、结束对战和索引 -1 下，渲染与点击均拦截；有效状态放行。
- 实际原生单打选招和双打切换到下一行动者通过；界面保护不提交动作。

尚未用两台真实客户端完成联机实测。请房主与参与测试的客户端均替换同一修订的主模组，重启后复测：在究极空间／主世界对战时，让另一玩家从其他维度 TP 到对战玩家身边；再测同维度 TP、正常单打／团战、本人跨维度离场、战斗结束与奖励界面。原始报告和解压日志仅保存在忽略的 `.cache`，不收入公开包。
