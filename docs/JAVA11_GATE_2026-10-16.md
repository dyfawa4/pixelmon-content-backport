# Java 11 强制门禁

2026-10-16，1.4.4 本地修订。只允许 Java 主版本 **11** 进入世界。

## 判定

使用 `Runtime.version().feature() == 11`，读取实际运行 JVM 的主版本。不限厂商、安装目录、11.0.x 补丁号、构建号或 LTS 标签；Oracle、Microsoft、Temurin、Zulu、Liberica 等 Java 11 均按同一条件放行。不会把本机路径写入生产判定，也不读取可以通过 `-Djava.version` 覆盖的字符串来放行。

## 非 Java 11 的行为

- 主菜单、世界列表、创建世界、多人游戏和连接界面被替换成阻挡页面。黑色背景，标题“警告⚠”及 Java11 字样为黄色，其余文字为白色；使用用户指定的两句提示，下方显示当前 Java 版本。
- ESC、返回和关闭界面不能绕过；页面只提供退出游戏。
- 同时在客户端真正加载现有世界、创建世界及启动服务器连接之前取消操作，避免其他入口越过菜单。
- 使用 Java 11 重新启动后自动放行，不需要改配置或删除任何文件。

门禁随客户端混入生效，不给专用服务端加载图形类。它负责阻止错误客户端进入世界，不宣称把旧 Pixelmon 改成兼容 Java 21。Java 8 无法加载本模组的 Java 11 字节码，本来就不能正常启动；其他 JVM 若在模组或资源加载前已经崩溃，也无法显示游戏内页面。

## 验证

- 主版本 0–50 的策略检查，仅 11 放行；模拟 8、11、16、17、21、25 执行生产菜单门禁和世界／连接回调。
- 检查普通界面、空界面、重复打开阻挡页、锁定后的其他页面和 Java 11 原对象返回；正确版本不调用阻挡 UI。
- 对实际 Forge Minecraft 类与原生 ConnectingScreen 应用 Mixin 并验证字节码，覆盖世界加载／创建及联网回调。
- 测试使用实际生产方法与隔离界面服务；不把它当作所有 Java 发行商和所有设备已逐一实测。
- 按用户要求另启动真正 Temurin Java 21.0.12.1 的独立客户端，目录 `.cache/manual-java21-gate-20261016`。未复制玩家世界，正式构建仍由 Java 11 编译。
