# 宝可梦编辑器中文输入

2026-10-16，1.4.4 本地修订。与已取消的技能回忆师适配无关；不修改学习表或对战规则。

## 使用

在简体中文界面中，宝可梦名称、精灵球种类、招式和携带物品支持输入或粘贴当前资源包显示的完整中文名称。宝可梦／球种可以输入中文或英文前缀后按 Tab 补全；招式与携带物也提供中文补全，同时保留英文名称和原物品 ID。

例如：`皮卡丘`、`戴帽子的皮卡丘`、`太乐巴戈斯`；`高级球`、`大师球`；`精神强念`、`太晶爆发`；`吃剩的东西`、`腐朽的剑`。保存后对应内部物种、球种、招式或携带物。

性格本来已能识别中文，此次保留原生解析并补充英文补全。特性、形态、体型继续使用原生本地化下拉框；材质下拉改为优先显示现有译名，没有译名时保留原名称。

中文显示名来自游戏当前语言与生效资源包，查询实时读取，不把当前语言表缓存成永久名单。注册后新增的宝可梦、球种与招式也走同一入口。

## 修复原因及边界

- 原生物种、球种输入响应仍把中文直接交给英文注册查询；现在只在编辑器入口解析成原生 ID，再执行原生响应、保存和网络流程。
- 原生携带物先尝试将输入当作资源 ID，中文在构造 ID 时抛出异常，导致后面的本地化查找无法运行。现在先映射携带物中文名；不完整、无效或重名的中文输入不再触发该异常，也不沿用旧物品作为成功选择，由原生保存校验拒绝。非携带物不通过中文入口新增资格。
- 招式在保存前统一为实际英文标识，保持已有 Attack 实例与 PP。重名译名不会随便选择注册表的首项；已有同名显示招式保留原对象，新选择可通过 `中文 [英文标识]` 的补全项区分，或使用英文名称。
- 物种／球种按完整名确认，不凭中文前缀自动更换；Tab 才执行补全。显式英文标识优先。
- 仅客户端编辑器及其当前物种／球种补全控件生效。服务器权限、编辑器资格、数值上限、保存包、昵称、导入格式及其他搜索／命令控件不改。

## 验证

`EditorChineseVerification` 对真实本体的四处目标执行 Mixin 应用，执行原生物种／球种输入响应与原生 `checkFields` 招式保存字节码；注册表和界面服务使用隔离测试数据，不启动游戏。

- 核对本体和回迁数据中的 1,027 个物种、40 种球、927 个招式、25 个性格的名称映射；927 招式中 925 项译名唯一，其余两项走重名保护及补全区分。
- 中文物种切换、重复同物种无额外更换、无效／半截名称不提交，智皮卡及太乐巴戈斯等新增物种通过。
- 中文高级球、英文大师球、无效球不替换通过。
- 未改动的中文十万伏特／精神强念保存后保留原 Attack 引用及已消耗 PP；切换太晶爆发、英文保存、原生清空招式，以及同名保护通过。
- 携带物中文解析在 ID 校验前成功，英文物品 ID 保留；非携带物、半截中文、旧物品残留保护、补全通过。
- 原生 25 个性格的中文与英文解析通过；物种中英文前缀补全、资源包译名变化、重名输入以及离开编辑器后的控件作用域通过。
