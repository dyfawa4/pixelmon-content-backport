# 索财灵金币与交互调研

日期：2026-10-11。状态：可行性调研；下面的新交互方案尚未实现，不进入玩家 README 的已有功能列表。

## 当前本地版本

`resources/backport/content.json` 将 `pixelmon_backport:gimmighoul_coin` 加入大师级宝可梦奖励箱物资。宝箱形态与徒步形态均通过原生 `InteractionEvolution` 道具右键进化，消耗 1 枚。`tests/EvolutionVerification.java` 的既有原生交互夹具也检查消耗 1 枚。先前手册、Shift 与测试地图写成了 999 枚后升级，现已纠正；此处没有改动进化成本或现有存档规则。

尚无野生索财灵右键发币、专用消失效果或此类交互的持久化领取标志；不能把奖励箱获取说成野外交互获取。

## 网上资料与版本差异

- [朱／紫金币机制](https://www.serebii.net/scarletviolet/gimmighoulcoins.shtml)：徒步形态在路标、岩石、遗迹等位置，交互取得金币；宝箱形态通过捕捉或击败获取。金币收集与探索相连。
- [Pixelmon 官方金币文档](https://pixelmonmod.com/wiki/Gimmighoul_Coin)：当前文档写 99 枚升级，提供合成和战斗掉落渠道；这是较新 Pixelmon 的规则，不能直接当作当前 1.16 回迁版的规则。
- [Pokémon GO 官方说明](https://pokemongo.com/news/gocoin)：999 枚进化，捕捉、伙伴行走和金色补给站获取；这也不是当前模组已接入的玩法。

## 可实施的本地方案

现有 999 号物种已具备 `chest` 和 `roaming` 模型/形态，可复用原生实体与服务端交互事件，无须另造平行宝可梦存储。

1. 野生徒步索财灵空手右键领取少量金币，随后产生声音/粒子并离开；保留宝箱形态正常捕捉、对战行为。
2. 宝箱形态通过成功捕捉或击败获得更多金币；所有渠道使用同一枚已注册硬币。来源同步到 Shift、JEI 和手册。
3. 发币前校验主手、野生状态、距离、无战斗/进化、存活状态；服务器在发放前标记实体已领取，避免双手事件、多人同时操作或重载重复领取。库存满时金币掉到现场，不吞掉。
4. 玩家已拥有的索财灵不被移除，也不能靠重复放出无限取币。世界刷新/再出现遵循独立规则，不能靠每次载入地图重新发币。
5. 增加专项交互台，供用户比较徒步与宝箱、满背包、多人争领、战斗中交互和保存重进；动态验收由用户完成。

可以先补充金币获取互动、保留现有进化规则；若要同时采用朱／紫的 999 枚升级进化，则需要额外修改原生进化条件、跨堆叠扣除、取消/失败回滚与旧存档兼容。该玩法成本变化应明确选择后再实现，不应只改文案。
