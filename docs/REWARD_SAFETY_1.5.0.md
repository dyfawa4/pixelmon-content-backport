# 1.5.0 空气奖励修复记录

用户报告 Boss 水晶灯火灵的战利品界面显示“空气”，并要求排查奖励箱、战利品的同类问题。本项顺序位于已验收的主菜单背景之后。

## 修复范围

- Boss `DropSet` 在载入和抽取前移除实际无效、且不含命令的候选奖励；保留有效奖励的权重、数量、NBT、原始概率和原生抽取次数。无有效候选时返回原生无掉落结果，不虚构奖励。
- Boss／普通宝可梦／训练家战利品在所有 `DropEvent` 监听器执行后整理一次，整理结果同时用于服务端领取队列与客户端数据包。有效 `DroppedItem` 对象和原奖励 ID 保持，不能因剔除空项错领邻项。
- 命令奖励不能因为没有实体物品被误删。只有展示图标使用有名称的纸张；实际领取继续走原生命令奖励，不额外发纸。
- 各级精灵球箱和异空间箱的源奖池剔除空项；全空池返回空结果而不调用空集合抽取。所有类型箱子的事件结果统一过滤，保留原领取／取消／背包满处理。
- 保留旧版仅野生非自定义大师箱的保底规则；不把这一保底扩大到普通箱、玩家箱、自定义箱或其他奖励。
- 极巨巢穴加权池拒绝空物品／非正权重，最终 `RaidDropsEvent` 结果在赋给玩家与生成展示任务之前过滤，太晶奖励也经过同一末端路径。空奖池和合法概率未命中仍可没有奖励。
- 自定义奖励界面在发送之前同步整理服务端项目列表与数据包列表，点击使用一致的编号。
- 旧版掉落解析中的 null 物品在复制前返回空结果，避免奖励处理时空指针。
- 道馆徽章等专属奖励继续由原道馆生成／发放路径负责；过滤只接收各自本次的奖励对象，不缓存、合并或在其他奖池使用。保留徽章本身和原编号，不添加通用徽章保底。

## 验证

完整 `build.ps1`、`check.ps1`（含新增原生奖励类的 Mixin 实际应用检查）已通过。新增 `tests/RewardGameTest.java` 在带显式标记的隔离测试客户端运行，不随正式模组打包。

隔离完整客户端 `.cache/manual-rewards-150-r5/reward-game-result.json` 八组实机验证通过：

1. null／空气／零数量清理、不可变输入、有效物品数量与 NBT、合法空结果。
2. 原生 Boss 奖池抽样 500 次，无空气；有效物品及命令奖励均能抽到；零概率不变；命令图标只用于展示。
3. 原生巢穴加权池抽样、取出与耗尽、无效旧物品复制保护。
4. 所有原生精灵球箱类型、玩家箱、自定义箱和野生大师箱保底范围；已载入各级箱子奖池有效。
5. 原生 Boss／训练家领取队列、奖励数据包往返、指定编号领取、全部领取、命令实际执行；移除编号不能领取邻项，不额外发纸。
6. 道馆徽章保留且领取一次，箱子／Boss／巢穴奖池没有串入道馆奖励。
7. 自定义奖励界面服务端与数据包列表一致。
8. 所有已载入 Boss 等级的原生奖励抽样没有无效物品／图标。

验证使用隔离测试世界中的原生类与真实服务器玩家，未实际打一遍每种 Boss／巢穴战斗；不能据此声称已穷尽未来第三方模组任意新增的奖励入口。测试辅助类未打入正式模组。
