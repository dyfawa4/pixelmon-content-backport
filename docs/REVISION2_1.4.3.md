## FTB 发现结构

原实现仅按配置结构注册表查找。修订保留原判断，未通过时再使用 Forge 结构类型注册 ID，校验玩家所在具体结构片段、真实起点和跨区块引用。结构 ID 必须带正确命名空间，例如实际注册的 `pixelmon:gyms`，不能填写建筑译名、模板池路径或随意拼写的名称。回迁道馆主题别名另核对真实主题；太晶巢穴别名还需对应真实巢穴实体。

没有登记为结构的手工建筑、装饰或普通地物，不会仅因外观类似自动完成任务。任务前置、进度和奖励逻辑沿用 FTB；不修改现有任务书配置。服务端须安装修订 JAR，联机测试双端统一版本。

## 戴帽子皮卡丘

进入与野生戴帽子皮卡丘的战斗时，向参战玩家提示“该宝可梦无法用大师球、公园球和起源球捕捉！”。同一场战斗每位玩家只提示一次。既有三种球的实际禁止捕捉规则保留；普通皮卡丘、忍蛙及 AI 模拟不触发此提示。

## 首次进入偶发等待

测试员报告第二次进入正常，原日志没有线程快照，不能认定所有启动等待均来自同一原因。日志最后的渲染线程活动位于 Lootr 装饰性赞助名单下载；实际原方法在持锁时同步请求 GitHub，未设置网络超时。修订跳过这项装饰名单下载，Lootr 容器、每位玩家的战利品与存档处理保持原逻辑。使用真实 Lootr 方法配合受控不可用网络的离线回归，原方法等待、修订方法立即返回。

## 验证边界

Java 11 构建及完整离线回归通过，真实 FTB StructureTask 和 Lootr ShoulderList 的 Mixin 变换通过。结构检测生产方法覆盖有效模组结构、错误命名空间、无效起点、片段外、未加载区块、道馆主题和太晶实体等情况。皮卡丘生产事件方法覆盖重复事件、双玩家、新战斗及普通种类／同队／非野生／模拟等反例。
