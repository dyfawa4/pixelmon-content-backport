# 1.4.1 智皮卡平原村庄刷新与查询修复

记录日期：2026-10-13。用户截图在平原村庄查询神兽时未发现戴帽子的皮卡丘，继多人入口修复一并处理。

实际不只是查询遗漏：原规则将`minecraft:village`传给Pixelmon的旧结构名称表，但该表使用Minecraft `Village`注册后的小写名称`village`，不是注册ID。查表失败使结构条件总是不满足。同时Pixelmon的WorldHelper只缓存当前区块的结构起点，不沿结构引用覆盖村庄其他区块，所以仅修改名字仍会漏判村庄范围。

修复将刷新JSON条件改为实际原生名称`village`；只针对独立智皮卡的村庄条件，转用Minecraft StructureManager及VILLAGE实际结构引用与有效起点判定。最终LegendarySpawnEvent.DoSpawn同样调用此方法；原生神兽查询的getSuitableSpawns与实际刷新因而共用一致条件。其他物种和结构条件仍调用原生WorldHelper。

保留`minecraft:plains`实际生成位置、真实村庄结构、70级、原生传奇刷新计时与额外减40个百分点的生成判定，不改为所有平原或其他群系村庄，也不往查询列表里凭空添加假候选。原生可用地面、位置和候选权重继续影响查询与实际生成。查询中候选权重百分比与底部全局神兽生成率不是同一个数。

回归检查独立读取实际Minecraft结构注册/名称表、Pixelmon结构缓存与神兽查询字节码，核对Village小写名称、原缓存缺少跨区块引用、修复的实际VILLAGE引用和有效结构起点、智皮卡专属条件作用范围及原规则保留。编译和96个实际目标的Mixin应用检查后，玩家在自然世界平原真实村庄重新查询并等待计时验收。不得用人工测试平台或纯静态结果宣称自然刷新已游戏验收。
