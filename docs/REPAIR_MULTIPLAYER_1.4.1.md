# 1.4.1 多人游戏入口修复

记录日期：2026-10-13。来源为用户提供的`错误报告-2026-10-13_20.54.43.zip`，不随源码分发用户日志或启动信息。

## 原因

崩溃为`StackOverflowError: mouseClicked event handler`。调用链反复出现`CustomMultiplayerScreen.init → DefaultServerList.tryFetchDefaultServers → backport$noAds → CustomMultiplayerScreen.lambda$init$0 → Minecraft.displayGuiScreen`。

本补丁屏蔽原生推广服务器下载时错误地同步调用了完成回调。原生完成回调会创建并打开一张新的多人界面，而新界面初始化又调用相同下载入口，造成无限递归。初始化标记位在回调后设置，且回调每次新建界面；单纯延迟或调整旧界面标记也不能正确解决。

## 修改

屏蔽下载入口时直接取消，不执行或调度完成回调：未下载、未修改服务器列表，无需重新打开界面。保留已有服务器列表加载、添加/编辑/删除、直接连接、局域网发现及此前推广隐藏功能。其他1.4.0宝可梦、战斗、城市与任务内容保持。

补丁元数据改为1.4.1，构建产物名读取元数据，避免覆盖已发布1.4.0文件。该修复包先在本地交付，不替换已发布附件。

## 验证

新增回归检查读取实际原生界面与回调字节码，验证上述新建界面的递归路径；检查修复不执行或调度Runnable。应用实际Mixin后的原生下载入口在隔离JVM执行20001次，包含非空回调、空回调及无参数入口；若回调被执行立即失败，不创建游戏、界面、网络连接或用户实例。

随后运行Java11构建与既有95个目标Mixin/ASM及全部离线回归检查。实际整合包多人界面的点击、服务器操作与连接效果交由玩家验收；离线验证不等同于连接服务器成功。
