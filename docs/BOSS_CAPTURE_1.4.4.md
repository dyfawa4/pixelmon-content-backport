# 1.4.4 野外 Boss 投球入口修复

用户反馈：朋友对红色 Boss 丰蜜龙能够投出大师球，随后显示挣脱；要求恢复原版野外 Boss 禁捕，明确所有颜色和等级都不能投球。本次不扩展智皮卡的物种禁球名单。

## 原生机制依据

- SpawnActionPokemon 抽取 BossTier，并给生成的真实 PixelmonEntity 设置 Boss 等级。颜色为等级的显示属性。
- BossTier.isBoss 按等级 ID 判定是否为 `notboss`，isNotBoss 为其反值；不按物种、颜色或名字猜测。
- PixelmonClientData 从真实战斗实体同步 bossTier；ClientBattleManager.canCatchOpponent 仅接受野生、非 Boss、未禁止捕捉的对手。
- ChooseBag 在由分类页打开 POKEBALLS 时调用 canCatchOpponent，但当前已经是精灵球分类时，点击具体球的分支不再次调用。已停留的分类是可达绕过入口。
- BagPacket 发布可取消的 SelectItem.Pre 后直接提交 setUseItem；取消时会在设置动作和消耗物品前返回，适合作为服务器复核入口。

以上来自当前安装 Pixelmon 本体代码。尚未收到朋友这次 Boss 对战的现场日志，因此不把可达绕过入口断言为其唯一触发过程。

## 修复行为

1. 客户端恢复背包时，若上一状态停留在精灵球分类但原生 canCatchOpponent 已不允许，重置分类。停留期间目标变化时，点击球前再次检查，沿用原版提示并返回主菜单。
2. 服务器在选球提交前检查当前玩家的活跃野外对手。任何原生 BossTier.isBoss 的个体均拒绝投球，所有球类型一致处理，拒绝后恢复仍可行动个体的选择菜单。
3. 不按红色单独识别，不标记或修改个体的永久不可捕捉状态，不把丰蜜龙加入禁球名单。不改 Boss 生成、颜色、等级、奖励、捕获率或大师球对普通野生的效果。
   回迁新增的铝钢桥龙、蜜集大蛇等新物种及新增形态生成的 Boss 同样受限；新增物种仍使用 PixelmonEntity 和原生 BossTier。判定代码不读取图鉴编号、物种名称、颜色或等级名称，不存在只覆盖原版种类的白名单，未来新增物种亦适用。
4. 治疗道具、友方 Boss、未上场／已倒下个体、玩家与 NPC 对手不受新增野外 Boss 选择判定影响；原生训练家禁捕继续存在。原生极巨巢穴与太晶巢穴保留各自战斗和战后捕捉流程。

## 回归与边界

BossCaptureVerification 动态执行本模组实际服务器及客户端辅助方法，使用本体原始 BossTier.isBoss/isNotBoss 和 ClientBattleManager.canCatchOpponent 字节码。枚举 10 个本体等级加 2 个自定义等级，逐项检查 5 类精灵球；覆盖分类残留、目标变化、原生不可捕捉位、训练家、治疗道具、归属、退场／倒下、巢穴、结束与模拟战斗。校验没有扣球、等待状态和已选择动作不变，恢复原生菜单。

BagPacket 的原生取消分支另有字节码检查；新 ChooseBag Mixin 通过实际类应用与字节码验证。隔离客户端／世界服务代替真实游戏，不宣称朋友原存档已经复测。

新增种类审计枚举内容目录 8 个 new 物种及独立智皮卡共 9 类；检查实际判定类没有按图鉴／种类／颜色筛选，全部共用原生 Boss 身份。新增形态也沿用所在原生物种的实体等级。

修复包含于 1.4.4。本轮最终构建已加载至 Java 11 独立测试客户端，用户确认测试没有问题；覆盖边界见验证记录。
