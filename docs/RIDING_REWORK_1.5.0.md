# 1.5.0 乘骑重构与验收

原乘骑、飞行、冲浪资格与归属、配置、秘传技能条件保留。服务端统一运动，客户端使用原生位置插值；取消被接管坐骑的旧马匹蓄力和旧飞行输入。

- 空格立即上升，释放悬停；沿用原下降键。下降触地后保持地面，重新按空格起飞。地面坐骑按下空格起跳，不获得飞行能力。
- 朝向由骑手同步，服务端按最短角度渐进转向；模型、人物与视角采用同一逐帧平滑朝向。水上速度与浮力单独处理。
- 双方碰撞箱和物理乘客位置保持原值。视觉座位在模型朝向坐标中采样动画躯干表面，并由头部定位肩部方向，避免转身时世界轴包围盒导致座位漂移。长颈与尖角通过摄像机净空处理，不裁剪模型。非 SMD 模型保留原显示位置。
- 下骑立即清理状态；自己的宝可梦不再附带原版 60 tick 再次上骑冷却。上骑仍走原实体交互资格与事件检查。看向别处时保留有效视觉座位，避免镜头恢复时跳变。
- 测试地图切换先同步传送位置，再同步乘客；短延时补同步仅用于仍骑乘同一实体的情况。测试命令 `/ridingtest 1` 至 `6`，大岩蛇为 `4`。

Java 11 构建和 Mixin 应用检查通过。r9 隔离客户端检查了飞行转向、拉普拉斯水面切换、大岩蛇移动和飞行坐姿；全部保持有效骑乘，大岩蛇连续三次下骑后立即通过原实体交互重新上骑成功。当前结果见 `RIDING_R9_GAME_RESULT.json`。用户随后实测确认大岩蛇已能上骑，动作基本通过，并要求准备发布。

早期起落、屋顶碰撞、地面跳跃、资格、蓄力条检查保留于 `RIDING_1.5.0_GAME_RESULT.json`，属开发历史。资源审计覆盖 1466 个身体模型和 5856 次旋转坐标回归检查，见 `RIDING_MODEL_AUDIT_1.5.0.json`；这不等同于所有物种、形态和动画均已实机验收。
